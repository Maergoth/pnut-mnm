# PNUT v1 release assessment

Updated October 10, 2026. This records the implemented features and validation for **1.0.0**. After testing the local candidate, the user authorized publication. Installed copies receive the release through PNUT's updater; development and release tasks preserve the installed App folder.

The original assessment reviewed 0.9.1 at commit `7c88e69d3168e63208ab12fdf60d0747a62a435b`. Its reproduced lifecycle, regex, persistence and release-gate problems drove the work below. Current evidence combines source review, synthetic fixtures, offscreen UI regressions, the user's local trial and disposable updater-helper tests. Live gameplay accuracy and long-session resource limits remain separate validation concerns.

## Exact new mode and Revenge List behavior

**Morality Adjustment** appears below Map updates. The top bar shows **🌼 Casual Mode 🌼** or **🔥 Elitist Scumbag Mode 🔥** with animated flames and opens that settings section. The red handle uses a sad emoji. The red mechanical lever requires a physical drag from the handle across most of its travel; a click or short drag cannot opt out. The brief animation/siren honors reduced motion and mute; data remains Casual until the pledge checkbox and explicit confirmation are accepted. Cancel, Escape and closing keep Casual active. Returning to Casual applies immediately and clears stale sensitive presentation and queued output.

Casual keeps own values and owned pets folded into self, plus rounded group averages only for a known group of at least three. It omits peer rows, rankings, individual drilldowns and unsafe source text. Unknown self identity fails closed. Small/unknown groups receive self-only presentation. Rounding and cohort rules reduce obvious inference; they are not a mathematical anonymity guarantee. The same policy applies to every app export, including automatic output and custom templates.

**Revenge List** is off by default. Its Settings switch hides the overlay Revenge tab, attacker/list panel and open pop-out when disabled, and returns an already selected Revenge tab to a normal meter. It is a PvP opt-in reminder, not a teammate comparison feature.

When enabled in confirmed full mode with known self identity, an eligible attacker gets a **+** prompt once per attacker per session. Prompts expire after **30 seconds**. Saving is explicit; the persistent list stores names and addition/latest-activity times, never chat text or damage. The main list and overlay offer **Pop out**, opening one independent passive window with synchronized Add/Remove controls. All three surfaces show newest activity first, with configurable **last days** and **entries shown** limits (defaults **30 days / 100 entries**, **All** for either). Limits only filter presentation. Name-only legacy entries keep unknown dates and remain visible until new activity supplies a date. Repeated attacks on saved players update activity through coalesced writes, flushed on quit and full backup. Manual Add and per-name Remove are available, including a compact overlay Add dialog. A new session resets prompt eligibility without deleting saved names. Casual hides saved names and prompts, clears queued candidates and closes the manual identity dialog. Automatic prompts require ASCII letters without spaces/symbols and exclude articles, self and second-person aliases. Manual additions accept arbitrary nonempty names or labels, including spaces, symbols and Unicode. This is a heuristic: a named NPC can resemble a player, so users must ignore inappropriate prompts. Enabling this switch does not bypass Morality Adjustment.

## Verification completed and pending

The final source regression run after executable cleanup completed with **1,266 tests run, 10 native UI checks skipped, and no failures** in 123.924 seconds. Coverage includes the actual drag/pledge flow, all four setup options through the real App, crop validation, preview cleanup and Casual protections. Tests cover cancellation, failed saves, current map/bar preferences and persisting the bar choice when the overlay is unavailable. Release-readiness checks include concurrent atomic writes, validated backup/rollback, both single-instance guards, worker-side map decode, provenance mismatch rejection, startup acknowledgement and real disposable PowerShell success/failure helpers. Executable cleanup tests verify post-exit removal, currently mapped image preservation, launch/cleanup coordination and malformed/modified/linked-file rejection. Real worker-emission tests cover GUI-thread Revenge delivery; stale queued attacks cannot reappear after opt-in or leaving Casual.

Local automated UI work uses **Qt offscreen**. Native Windows visibility/restart probes require explicit `PNUT_NATIVE_UI_TESTS=1`, use isolated desktops, have emergency exit timers and guaranteed subprocess cleanup. The isolated Windows CI runner opts in; ordinary local suites skip them. Build and extracted smoke force offscreen and never start capture or map downloads. Native probes were stopped after unwanted map windows appeared during a prior test run; their callback signatures and cleanup were corrected. No further visible UI checks are part of this local automation.

**The separate local candidate build and portable ZIP passed startup validation and were tested locally before publication was authorized.** Candidate checks used matching dirty Development provenance; published assets require a clean committed build. The Windows workflow repeats regressions, isolated native probes, clean freezing and extracted ZIP validation. Offscreen startup checks cover imports, window construction and output policy; they do not establish live gameplay behavior. Use the [local test checklist](LOCAL_V1_TEST.md).

Remaining human and environment validation:

1. **Environment coverage:** the local user trial is complete for publication approval. A fresh supported Windows installation without development Python/Qt, full frozen update/failed-boot recovery and audio/speech device coverage remain additional trials. Embedded version/provenance and extracted ZIP startup are automated release checks.
2. **Gameplay coverage:** setup, crop/OCR readability, lost-game recovery, slow Stop/Start and mode changes during live capture. Check labeled rapid/wrapped chat, scroll/occlusion, group/pet changes, named NPCs, healing/CC/loot and estimates against expected totals. Invisible lost lines cannot be proven complete from the resulting log.
3. **Privacy/interaction coverage:** physical lever travel, keyboard pledge/cancel/Escape, siren/mute/reduced motion, every export channel, existing selected dialogs and queued speech; Revenge prompts/manual controls/default-off hiding through mode and session changes.
4. **Resource/usability coverage:** representative long sessions and large imports, full-size maps, failed network/disk writes, DPI/resolution and mixed monitors, tray/map/overlay restoration, keyboard-only navigation and assistive technology. Define p50/p95 latency and memory budgets from representative machines. An eight-hour soak is proposed, not completed.

Known follow-ups beyond those trials: pipeline timings have bounded 256-sample p50/p95 histories, but no process working-set metric yet. Interrupted imports are discarded on archive startup and cooperative cancellation removes staged records. Archive retention does not prune separately captured raw log files. Very large maps still allocate full-resolution image surfaces; preview levels/tiles need a separate design if measured memory warrants them.

## Original performance evidence and its limits

These measurements were taken before the v1 cache/archive changes and remain baseline evidence only. They are warm local synthetic operations, not current end-to-end gameplay latency claims. Encounter fixtures used two actors without complex vocabulary; session fixtures repeated loot entries. Native image memory, rendering, disk contention and real histories were not included.

| Isolated full rebuild | 1,000 entries | 10,000 entries | 50,000 entries |
| --- | ---: | ---: | ---: |
| Encounter snapshot | 1.57 ms | 14.99 ms | 73.62 ms |
| Session snapshot | 0.93 ms | 7.88 ms | 39.30 ms |

The original parser fixture processed 10,000 mixed lines in about 369 ms (roughly 27,000 lines/second). Its small OCR fixture took about 10.75 ms for Windows OCR and 3.84 ms for preprocessing. Those narrow results favored eliminating repeated aggregation and GUI work over a broad parser rewrite. The implemented caches now avoid repeated raw-history aggregation on idle updates, but no new cross-machine performance improvement is claimed here.

Ancient Crypt's 8400 × 9300 dimensions imply approximately **298 MiB for one decoded 32-bit surface**, before temporary/pixmap allocations; this is a dimension estimate, not measured resident memory. The original isolated 100,000 Event objects with distinct text allocated **33.27 MiB**; that excludes native images and the rest of PNUT. Worker decoding, bounded previews and durable archives address responsiveness/growth pathways but do not replace an endurance and working-set measurement.
